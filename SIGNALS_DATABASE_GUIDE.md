# Trading Signals Database Guide

## Overview

The Trading Signals Database is a new feature that automatically stores and displays all trading signals generated by the ForexAnalyzer across different timeframes. This provides a complete historical record of signals with detailed entry/exit points, take profits, and stop losses.

## Features

### 1. **Automatic Signal Storage**
- Every time you run an analysis, BUY and SELL signals are automatically saved to the database
- Signals are stored with complete trade plan details including:
  - Signal type (BUY/SELL)
  - Strength level (confidence 0-100%)
  - Multiple entry points (immediate, pullback, aggressive)
  - Multiple take profit levels (quick, conservative, extended)
  - Multiple stop loss levels (tight, standard, wide)
  - Risk:Reward ratio
  - Market context (trend, momentum, reversals)

### 2. **Timeframe-Based Organization**
- Signals are organized by timeframe (15m, 1h, 4h, 1d)
- Each timeframe maintains its own signal history
- View up to last 20 signals per timeframe

### 3. **Weekly Rotation**
- Active signals are kept for 7 days
- After 7 days, signals are archived (marked inactive)
- Archived signals are permanently deleted after 30 days
- Automatic cleanup runs daily via the scheduler

### 4. **UI Display in Scanner Page**
- New "Signal History & Recommendations" section at the bottom of Scanner page
- Select any asset to view its signal history
- Signals are displayed in tabbed view by timeframe
- Color-coded tables showing:
  - BUY signals in green
  - SELL signals in red
  - Strength categories (WEAK, MODERATE, STRONG, VERY_STRONG)

## How to Use

### Viewing Signal History

1. **Navigate to Scanner Page** (`📊 Scanner`)
2. **Scroll to "Signal History & Recommendations"** section
3. **Select an asset** from the dropdown
4. **View the summary card** showing signal counts by timeframe
5. **Click on timeframe tabs** to see detailed signal tables
6. **Expand "View Latest Signal Details"** to see complete trade plan

### Signal Table Columns

| Column | Description |
|--------|-------------|
| **Date** | When the signal was generated |
| **Signal** | BUY or SELL |
| **Strength** | WEAK, MODERATE, STRONG, or VERY_STRONG |
| **Confidence** | Signal confidence percentage |
| **Entry** | Primary entry point price |
| **Stop Loss** | Standard (2 ATR) stop loss |
| **Take Profit** | Conservative target price |
| **R:R** | Risk:Reward ratio |
| **Trend** | Overall trend direction |
| **Price** | Market price when signal was generated |

### Understanding Signal Strength

- **VERY_STRONG** (≥75%): High confidence, multiple indicators aligned
- **STRONG** (60-74%): Good confidence, most indicators agree
- **MODERATE** (45-59%): Acceptable confidence, mixed signals
- **WEAK** (<45%): Low confidence, conflicting indicators

### Signal Details View

Each signal includes:

#### Entry Points
- **Entry 1 (Immediate)**: Current market price entry
- **Entry 2 (Pullback)**: Better entry on a pullback
- **Entry 3 (Aggressive)**: Early entry before full confirmation

#### Take Profit Levels
- **TP1 (Quick)**: Nearest resistance/support for quick profit
- **TP2 (Conservative)**: 2x ATR target (recommended)
- **TP3 (Extended)**: Maximum target based on major S/R levels

#### Stop Loss Levels
- **SL Tight (1 ATR)**: For aggressive traders
- **SL Standard (2 ATR)**: Recommended stop loss
- **SL Wide (3 ATR)**: For swing traders, more breathing room

#### Market Context
- **Trend**: Current trend direction (BULLISH/BEARISH/NEUTRAL)
- **Momentum**: Momentum analysis
- **Reversal**: Alerts if potential reversal detected

## Database Structure

### Location
- Database file: `data/signals.db`
- Separate from analysis database for better organization

### Schema
```sql
CREATE TABLE trading_signals (
    id INTEGER PRIMARY KEY,
    asset_symbol TEXT,
    timeframe TEXT,
    signal_type TEXT,           -- BUY or SELL
    strength_level REAL,        -- 0-1 confidence
    strength_category TEXT,     -- WEAK/MODERATE/STRONG/VERY_STRONG

    -- Entry points
    entry_point_1 REAL,
    entry_point_2 REAL,
    entry_point_3 REAL,
    entry_points_json TEXT,

    -- Take profits
    take_profit_1 REAL,
    take_profit_2 REAL,
    take_profit_3 REAL,
    take_profits_json TEXT,

    -- Stop losses
    stop_loss_tight REAL,
    stop_loss_standard REAL,
    stop_loss_wide REAL,
    stop_losses_json TEXT,

    -- Risk metrics
    risk_reward_ratio REAL,
    risk_percentage REAL,

    -- Context
    trend_direction TEXT,
    momentum TEXT,
    reversal_detected INTEGER,
    reversal_type TEXT,

    -- Metadata
    current_price REAL,
    created_at TEXT,
    week_number INTEGER,
    year INTEGER,
    is_active INTEGER          -- 1 = active, 0 = archived
)
```

## Automatic Cleanup (Weekly Rotation)

The scheduler automatically manages signal lifecycle:

### Daily Cleanup Process
1. Runs once per day (every 24 hours)
2. Archives signals older than 7 days (sets `is_active = 0`)
3. Deletes archived signals older than 30 days
4. Logs cleanup statistics

### Manual Cleanup (if needed)

```python
from src.database.signals_db import SignalsDB

# Initialize database
signals_db = SignalsDB()

# Archive signals older than 7 days
archived = signals_db.cleanup_old_signals(days=7)
print(f"Archived {archived} signals")

# Delete archived signals older than 30 days
deleted = signals_db.delete_archived_signals(days=30)
print(f"Deleted {deleted} old archived signals")
```

## Integration with Analysis

### How Signals Are Stored

When you run an analysis (via Scanner or analyze_pair()):

1. **Analysis runs** across all timeframes (15m, 1h, 4h, 1d)
2. **Signals generated** for each timeframe with enhanced filters
3. **Only BUY/SELL signals saved** (HOLD signals are not stored)
4. **Trade plans created** with multiple entry/exit points
5. **Signals saved to database** with complete trade plan details
6. **Analysis also saved** to analysis database for tracking changes

### Signal Generation Flow

```
Data Fetch → Technical Analysis → Signal Generation → Enhanced Filters →
Trade Plan Creation → Signal Storage → UI Display
```

### Enhanced Filters Applied
- Minimum confidence thresholds per timeframe
- Minimum indicator agreement requirements
- Momentum strength filters
- Reversal detection warnings
- Higher timeframe confirmation

## Best Practices

### 1. **Review Signal History Before Trading**
- Check multiple timeframes for confluence
- Look for strong signals (≥60% confidence)
- Verify trend direction aligns with signal
- Watch for reversal warnings

### 2. **Use Multiple Entry Points**
- Entry 1 for immediate execution
- Entry 2 for better price on pullback
- Entry 3 for early positioning (more risk)

### 3. **Manage Risk with Multiple Stop Losses**
- Use Standard SL (2 ATR) for most trades
- Tight SL for aggressive/short-term trades
- Wide SL for swing trades with more volatility

### 4. **Scale Out with Multiple Take Profits**
- Take partial profit at TP1 (quick target)
- Hold for TP2 (conservative, recommended)
- Let remaining position run to TP3 (extended)

### 5. **Monitor Signal Age**
- Fresher signals (same day) are more relevant
- Older signals may be outdated if market conditions changed
- Use signal date to assess current relevance

## Troubleshooting

### No Signals Showing
- **Cause**: No analysis has been run yet
- **Solution**: Run a scan or analyze an asset to generate signals

### Signal History Not Updating
- **Cause**: Database connection issue
- **Solution**: Check if `data/signals.db` exists and has write permissions

### Old Signals Not Rotating
- **Cause**: Scheduler not running
- **Solution**: Run `python run_scheduler.py` to enable automatic cleanup
- **Alternative**: Manually run cleanup with `signals_db.cleanup_old_signals()`

### Signal Details Missing
- **Cause**: Trade plan was not approved (risk too high)
- **Solution**: Normal behavior - only approved trade plans have full details
